# Overview
The Run a Match flow covers the full operational lifecycle of a tournament fixture:
```text
Scheduled
  ↓
Pre-Match Checks
  ↓
Live
  ↓
Completed
```

Exceptional paths:
```text
Live → Postponed
Live → Cancelled
Scheduled/Completed → Walkover correction
Postponed → Continue
Postponed → Restart
```

Matches are controlled independently. Multiple matches may be live at the same time.

---
# Entering Match Control
From the Matches page, a scheduled match exposes:
```text
Start Match
```

The host may also prepare lineups in advance without changing the match state.
Each match has its own independent Match Control page.
## Desktop
Teams may be shown side-by-side.
## Mobile
Teams should stack vertically.

---
# Pre-Match Requirements
When the host selects **Start Match**, the system checks:
- match has a date
- Team A has a valid lineup
- Team B has a valid lineup

If any requirement is missing, the host must complete it before kickoff.
Formation is part of the lineup.
A simple pre-match checklist is sufficient:

```text
Match date        ✓
Team A lineup     ✓
Team B lineup     ✓

[ Start Match ]
```

---
# Lineup Setup
Each team lineup requires:
- formation preset
- starting players
- substitutes
## Formation
Formation presets depend on tournament team size.
## Starting Players
The number of starters must exactly match the configured tournament team size.

Example:
```text
8-a-side tournament → exactly 8 starters
```
## Substitutes
- substitutes are supported
- there is no minimum number of substitutes
- rolling substitutions are allowed later during the match
## Player Eligibility
A lineup may include:
- players permanently assigned to that team
- unassigned tournament players as guests

A player permanently assigned to another team may **not** guest for a different team.
An unassigned player used in a match does not become permanently assigned to that team.
The same player may not appear in both teams' lineups for the same match.
Guest players should be visibly marked.
## Goalkeeper Designation
Goalkeeper designation is optional.
However:
- if one team designates a goalkeeper
- the opposing team must also designate one

Any eligible player may be designated as goalkeeper regardless of registered position.
## Saving Lineups
A lineup may only be saved once it is valid.
Lineups may be prepared before kickoff while the match remains `Scheduled`.
Lineups remain editable after kickoff to support late-arriving players.
Every lineup change made after kickoff must create an audit-log entry.

---
# Starting the Match
After all pre-match requirements are valid, show a final confirmation containing:
- Team A lineup
- Team B lineup
- match date
- Start Match action

If this is the first match to start:
```text
Tournament: Active → In Progress
```

The structural lock applies immediately.
The following tournament structure becomes permanently locked:
1. Tournament format
2. Team size
3. Participating teams
4. Number of groups
5. Group membership
6. Qualification rules
7. Fixture rounds / competition structure

Starting the match changes:
```text
Scheduled → Live
```

A started match does not return to `Scheduled`.

If the tournament is published:
- the match becomes publicly visible as Live immediately

If the tournament is unpublished:
- the match may still be run normally
- no public live view is exposed

After kickoff, Match Control switches into a focused live-match layout.

---
# Live Match Control
The live screen prioritises:
1. current score
2. primary event actions
3. chronological event feed
4. secondary match-state actions
## Primary Event Actions
```text
Goal
Card
Substitution
Own Goal
```

Assist is recorded as part of the Goal flow.
### Recording a Goal
Flow:
1. choose scoring team
2. choose scorer
3. optionally choose assister
4. save event

Every normal goal must have a scorer.
Assists are optional.
Eligible scorer options should reflect players participating in the match.

The event immediately:
- updates the score
- appears in the event feed
- updates the public live match view
- contributes to player/team statistics, subject to match-state rules
### Recording a Card
Flow:
1. choose team
2. choose player
3. choose Yellow or Red
4. save event

A substitute on the bench may receive a card.
Cards appear immediately in the event feed.
### Recording a Substitution
Flow:
1. choose player off
2. choose player on
3. save event

Rules:
- rolling substitutions are allowed
- a player substituted off may return later
- every substitution records both player off and player on
- substitution ordering is preserved
- substitution limits are not enforced in V1
### Recording an Own Goal
Flow:
1. choose conceding team
2. choose player responsible for own goal
3. save event

Result:
- opponent score increases by one
- own goal is attributed to the responsible player
- own goal is tracked separately from normal goals

Own goals do not count toward the player's normal goal tally.
## Secondary Live Actions
Actions such as:
- Postpone
- Cancel
- End Match

should live in an overflow/secondary-actions menu rather than cluttering the primary event controls.

---
### Ending a League or Group Match
For a league/group match:
```text
End Match
  ↓
Final Review
  ↓
Confirm Result
  ↓
Completed
```

Final review shows:
- final score
- event list
- winner or draw

On confirmation:
- match becomes `Completed`
- standings recalculate
- player statistics recalculate
- team statistics recalculate
- public pages update immediately

Tournament completion readiness is handled on the Dashboard.

---
### Knockout Match Flow
A knockout match may progress through:
```text
Regulation
Extra Time
Penalties
```
#### End Match Action
In knockout matches, selecting **End Match** presents the valid next actions based on the current match phase and score.

Example:
```text
[ End Match ▼ ]

- Complete Match
- Continue to Extra Time
- Continue to Penalties
```

Exact options depend on the tournament's configured knockout rule and current match state.
#### Extra Time
When continuing to extra time:
- match remains Live
- phase changes to `Extra Time`
- normal goals/cards/substitutions continue
- each event is tagged to the Extra Time phase

The host may later:
- complete the match
- continue to penalties
#### Penalty Shootout
When continuing to penalties:
- phase changes to `Penalties`
- each penalty attempt is tracked individually
- shootout event ordering is preserved

Penalty shootout goals:
- affect the shootout score
- do **not** count toward player normal-goal statistics

The host ends the match after the shootout winner is established.
### Final Match Confirmation
Before a match is completed, show a final review:
- score
- phase scores where applicable
- events
- winner/draw

The host explicitly confirms the result.

Once confirmed:
- match becomes `Completed`
- standings update
- bracket progression updates
- player statistics update
- team statistics update
- public pages update immediately

For knockout matches, regulation, extra-time, and penalty scores are stored separately.

---
# Event Feed
Every match event appears immediately in chronological order.

Supported event types:
- Goal
- Assist
- Own goal
- Yellow card
- Red card
- Substitution
- Penalty shootout attempt

Each event supports edit/delete controls where the tournament is still editable.

Event edits must recalculate affected:
- score
- standings
- player statistics
- team statistics
- awards
# Editing a Completed Match
A completed match remains `Completed` while corrections are made. There is no separate **Editing** state.

Before editing, show a warning:
> Changes to this match may affect standings, statistics, awards, and knockout progression.

Corrections require an explicit **Save**.

On Save:
- score recalculates
- standings recalculate
- bracket progression recalculates
- player/team stats recalculate
- public pages update
- audit log records the change

---
# Postponing a Live Match
A live match may be postponed.

State transition:
```text
Live → Postponed
```

Postponement preserves:
- score
- lineups
- substitutions
- events
- cards
- match phase
- audit history

While Postponed, the match does **not** count as completed for:
- Played (`P`)
- standings
- knockout progression
- tournament-completion checks

Statistics calculations must respect match state so postponed-match events do not become final competition stats.

---
# Resuming a Postponed Match
A postponed match offers two paths.
## Continue Match
```text
Postponed → Live
```

Continue from the preserved state:
- current score
- lineups
- events
- substitutions
- match phase

The fixture keeps the same identity.
## Restart Match
The same fixture is replayed from scratch.

Restart behaviour:
- same fixture/match identity is retained
- previous attempt is preserved in audit/history
- previous attempt's events stop contributing to official stats
- official score resets to 0–0
- match phase resets to Regulation
- fresh lineups may be entered
- match returns to Live when restarted

Only the eventual completed state counts toward:
- standings
- Played
- bracket progression
- official tournament statistics

---
# Cancelling a Match
A match may be cancelled.
Cancellation requires a reason.

Cancelled matches:
- remain internally available to the host
- preserve all historical data and audit entries
- are hidden from the public tournament experience
- do not affect standings
- do not affect bracket progression
- do not count toward Played

---
# Walkovers
Walkovers are supported.

Default awarded result:
```text
3–0
```

A walkover does not require lineups.

For conversion of an existing match to walkover:
1. choose winning team
2. system sets result to 3–0
3. normal match events stop contributing to official statistics
4. previous events remain preserved in audit/history
5. standings/bracket/stats recalculate

A completed match may be corrected into a walkover while tournament editing is still allowed.

---
# Clean Sheets
Player clean sheets are calculated automatically.

Any player who participated as goalkeeper receives a clean sheet when their team conceded zero goals. All members of the team also receive clean sheets.

Because goalkeeper designation is optional:
- clean-sheet attribution only applies when goalkeepers were designated for both teams

Goalkeepers may be unassigned tournament players.

---
# Audit Requirements
Audit entries are created for meaningful changes, including:
- match started
- lineup changed after kickoff
- event added
- event edited
- event deleted
- match postponed
- match resumed
- match restarted
- match cancelled
- result corrected
- match converted to walkover
- match completed

Where possible, audit entries should store before/after values.

---
# Completed Tournament Behaviour
Once the tournament reaches:
```text
Completed
```

Match Control becomes permanently read-only.

No further actions are allowed:
- no lineup changes
- no event changes
- no result corrections
- no walkover conversion
- no cancellation
- no postponement
- no restart
- no match-state mutation

Historical and public information remains viewable.

```text
   ↓

   ↓
Final kickoff confirmation
   ↓
Live
   ├── Goal

   ├── Substitution
   ├── Own Goal
   ├── Postpone
   │     ├── Continue
   │     └── Restart
   ├── Cancel
   └── End Match
         ├── Complete
         ├── Extra Time
         │      ├── Complete
         │      └── Penalties
         └── Penalties
                ↓
             Complete
                ↓
           Final Review
                ↓
          Confirm Result
                ↓
            Completed
```
